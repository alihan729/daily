# Трекер лечения — `daily`

Личное локальное веб‑приложение (**один файл `index.html`**) для ежедневного отслеживания лечения: **кожа (акне) · глаза · добавки**. Без бэкенда, аккаунтов и сборки. Все данные — в `localStorage` браузера, в сеть ничего не уходит. Опубликовано на **GitHub Pages**.

> 🧭 **Если ты открыл этот файл, чтобы продолжить работу над проектом (человек или ИИ‑ассистент):** пролистай до раздела **[«Полный контекст для разработки»](#полный-контекст-для-разработки)** — там вся архитектура, текущее наполнение, пошаговые рецепты изменений, деплой и грабли. Начни с него.

## Живая версия
- **Сайт:** https://alihan729.github.io/daily/
- **Репозиторий:** `alihan729/daily` → GitHub Pages (ветка `main`, папка `/root`). Репозиторий **должен быть Public** (иначе Pages отключается и сайт отдаёт 404).
- **На телефоне:** добавлено на домашний экран iPhone (Safari → «Поделиться» → «На экран „Домой“»). Данные хранятся в браузере телефона и переживают обновления сайта.

## Что умеет (кратко, для пользователя)
Внизу 6 вкладок: **🧴 Кожа · 👁 Глаза · 💊 Добавки · 📊 Прогресс · 📜 История · ⚙️ Настройки**.
- **Кожа / Глаза / Добавки** — ежедневные чек‑листы, разбитые на блоки по времени дня. У каждого пункта: описание (доза/как принимать), цветная пометка времени приёма (🟢 во время еды / 🟠 после еды / ⚪ без привязки), для препаратов с курсом — «день N/M» и «ещё N дней».
- **Листание по дням** — стрелки ‹ › вверху: вернуться в прошлый день и дотыкать пропущенное (в будущее нельзя). «Сегодня →» возвращает к текущему дню.
- **Автозавершение по сроку** — когда дни препарата кончились, он становится неактивным («Курс завершён ✅»).
- **Остановить отдельный препарат** — на карточке кнопка «закончился» → пункт неактивен («Закончился ✅»), с кнопкой «↻ вернуть». Обе дозы одного препарата останавливаются вместе.
- **Остановить весь уход за глазами** — отдельная кнопка на вкладке «Глаза» (у кожи её нет — там чёткие сроки).
- **Прогресс** — остаток дней по препаратам кожи + приёмы у врача с отсчётом + бессрочные пункты по разделам.
- **История** — журнал по дням, счёт раздельно: 🧴 кожа · 👁 глаза · 💊 добавки. Кнопка «Отмечать в этом дне» открывает день для правок.
- **Настройки** — дата старта курса кожи; приёмы у врача (добавить/изменить/удалить); экспорт/импорт JSON (резервная копия); полный сброс.

## Как обновлять сайт
1. Правишь `index.html`.
2. Заливаешь в репозиторий `alihan729/daily`: на сайте **Add file → Upload files → перетащить `index.html` → Commit changes**; или `git push`.
3. Через ~1–2 минуты GitHub Pages пересобирается, ссылка обновляется. На телефоне — полностью закрыть приложение и открыть заново.

# Полный контекст для разработки

Здесь всё, что нужно, чтобы продолжить: как устроен код, что уже есть, как аккуратно добавить/убрать/поправить, как проверить и задеплоить.

## 1. Принципы
- **Один файл** `index.html` = разметка + inline `<style>` + inline `<script>`. Никакой сборки, npm, зависимостей, фреймворков. Работает офлайн, открывается двойным кликом (`file://`) и на GitHub Pages.
- **Данные только локально:** `localStorage`, ключ `acneTracker.v1`. В сеть ничего не отправляется.
- **Мультиразделы («курсы»)** через поле `course`: `skin` (кожа, значение по умолчанию — поля может не быть), `eyes` (глаза), `supplements` (добавки). Экраны: три чек‑листа + Прогресс + История + Настройки.
- **Медицинские данные не выдумывать.** Препараты/дозы/сроки добавлять только по факту назначений от пользователя.

## 2. Данные (правится в основном ЭТО — начало `<script>`)
**Константы:**
- `SCHEMA` — версия формата данных (для миграций). Сейчас `3`.
- `DEFAULT_START='2026-08-31'` — старт курса кожи (день 1).
- `EYES_START='2026-09-17'`, `SUPP_START='2026-09-27'` — старты разделов глаз и добавок.
- `COURSE_START = { eyes:EYES_START, supplements:SUPP_START }` и `courseStart(course)` → старт нужного раздела (иначе `state.startDate`). Нужно, чтобы прошлые дни в «Истории» до старта раздела НЕ считались (пункты там `notstarted`).
- `DEFAULT_APPTS` — приёмы у врача по умолчанию (`[{date,label}]`).
- `TIMING` — карта пометок еды (`before/during/after/free` → текст + css‑класс тега).

**`BLOCKS`** — секции по времени дня. Поля: `{ id, course?, title, subtitle, icon, note? }`. Нет `course` ⇒ `skin`. `note` — подсказка под заголовком блока.

**`TASKS`** — пункты чек‑листа. Поля:
- `id` — уникальный (напр. `ursosan_am`). Ключ для отметок в `history`.
- `course?` — `'eyes'` / `'supplements'`; нет поля ⇒ `skin`.
- `block` — id блока, в котором показывать.
- `name` — **отображаемое имя И ключ группировки/остановки.** Две дозы одного препарата = два TASKS с **одинаковым `name`** (напр. `ursosan_am` и `ursosan_pm` оба `name:'Урсосан 250 мг'`). Кнопка «закончился» останавливает по `name` → обе дозы разом.
- `detail` — текст описания (доза, как принимать).
- `timing?` — `before/during/after/free` → цветной тег еды. Для наружных/капель обычно не ставится.
- `duration` — число дней курса, либо `null` = бессрочно (рутина/добавки; авто‑завершения по сроку нет).
- `special?` — `'baziron'` (схема «через день» первые 14 дней).

**`COURSE_MEDS`** — список препаратов кожи с длительностью для экрана «Прогресс» (прогресс‑бары, остаток дней). Держать синхронно с TASKS кожи, у которых есть `duration`.

## 3. Состояние и хранение
```
state = {
  startDate,                 // старт курса кожи (редактируется в Настройках)
  appointments: [{date,label}],
  eyesEnd,                   // дата остановки ВСЕГО ухода за глазами | null
  stopped: { "Имя препарата": "YYYY-MM-DD" },  // остановленные отдельные препараты (ключ = name)
  history: { "YYYY-MM-DD": { taskId: true } }  // отметки по дням (хранятся только true)
}
```
- `save()` → `localStorage['acneTracker.v1'] = JSON({ v:SCHEMA, ...state })`.
- `load()` → парсит; если `p.v !== SCHEMA` вызывает `migrate()`.
- `migrate()` — по версии. Правило: при изменении дефолтов, которые уже могли сохраниться у пользователя, **поднять `SCHEMA`** и добавить ветку, меняющую ТОЛЬКО точное старое авто‑значение (чтобы не затереть ручные правки). Историю не трогать.

## 4. Статус пункта — `statusOf(task, dateKey)` → `{ s, cd, reason? }`
`cd` = день курса = `dayDiff(courseStart(task.course), dateKey) + 1`. Порядок проверок:
1. `cd < 1` → `notstarted` (до старта раздела).
2. глаза целиком остановлены (`task.course==='eyes' && state.eyesEnd && dateKey >= eyesEnd`) → `completed`, `reason:'eyes'`.
3. препарат остановлен вручную (`state.stopped[task.name] && dateKey >= дата`) → `completed`, `reason:'user'`.
4. срок вышел (`duration!==null && cd>duration`) → `completed`, `reason:'course'`.
5. Базирон, первые 14 дней, чётный день курса → `rest` (день‑пропуск «через день»).
6. иначе → `active`.

## 5. Рендер
- **`renderChecklist(course, elId)`** — универсальный экран чек‑листа. Обёртки: `renderToday`(skin,`screen-today`), `renderEyes`(eyes,`screen-eyes`), `renderSupp`(supplements,`screen-supp`). Фильтрует BLOCKS/TASKS по `(x.course||'skin')===course`. Баннер приёмов у врача — только `course==='skin'`. Кнопка «Завершить весь уход» — только глаза. Заголовок дня (`dayLabel`) зависит от раздела.
- **`cardHTML(task, dateKey)`** — карточка по статусу: `active` (чекбокс + тег еды + чипы «день N/M»/«ещё N дней»/«ежедневно» + кнопка `data-stop` «закончился»); `completed` по `reason` (`user`→«Закончился ✅» + `data-resume-med` «вернуть»; `eyes`→«Уход остановлен ✅»; `course`→«Курс завершён ✅»); `rest` (пропуск); `notstarted` («начнётся …»).
- **`renderProgress`** — препараты кожи из `COURSE_MEDS` (остаток дней/дата конца/бар; учитывает ручную остановку) + приёмы у врача + бессрочные пункты по разделам (`noDurationNames(course)` + `medDailyStatus(name, courseStopped?)`).
- **`renderHistory`** — по дням от сегодня до старта кожи; счёт **раздельно по разделам**: `🧴 s/S · 👁 e/E · 💊 c/D` (бакет показывается, только если раздел активен в этот день). ⚠️ При добавлении нового `course` обязательно добавить его бакет сюда, иначе пункты свалятся в «кожу».
- **`renderSettings`** — дата старта, приёмы (CRUD), экспорт/импорт, сброс.

## 6. Навигация и листание дней
- `viewDate` — открытый день (общий для всех трёх чек‑листов). `setViewDate(k)` с клампом `[старт кожи; сегодня]`. Стрелки — `data-nav` `prev`/`next`/`today`.
- `go(screen)` — переключение экранов (`today/eyes/supp/progress/history/settings`). `renderActiveChecklist()` перерисовывает активный чек‑лист (после отметки/остановки).
- `maybeRefreshDay()` на `focus`/`visibilitychange`: при смене реального дня переходит на новый день, если смотрели «сегодня» (иначе оставляет открытый прошлый день).
- Обработчики: `attachChecklistHandlers(el)` навешивается на `screen-today/eyes/supp`. Делегирование в порядке: `data-stop` → `data-resume-med` → `data-eyes` → `data-nav` → `.task.clickable` (тоггл чекбокса). В `keydown` есть гард `if(e.target.closest('button')) return` — чтобы кнопки на карточке не триггерили чекбокс.

## 8. Рецепты типичных изменений
**Добавить препарат в существующий раздел:** добавить объект в `TASKS` (`id` уникальный; `course` как у раздела или без для кожи; `block` — существующий id блока; `name`, `detail`; `duration` число или `null`; при желании `timing`). Если препарат с длительностью и он на коже — добавить и в `COURSE_MEDS`.

**Убрать препарат:** удалить его объект(ы) из `TASKS`. (История прошлых отметок по его `id` останется в localStorage, но показываться не будет.)

**Изменить дозу/описание/время/срок:** поправить поля `detail`/`timing`/`duration`/`block` у нужного TASKS.

**Добавить НОВЫЙ раздел (напр. «Зубы»):**
1. Константа старта (если свой) + добавить в `COURSE_START`.
2. `BLOCKS`: секции с `course:'teeth'`.
3. `TASKS`: пункты с `course:'teeth'`.
4. Разметка: `<section id="screen-teeth" class="screen hidden">` в `<main>` + кнопка вкладки `<button class="tab" data-screen="teeth">…` в `<nav>`.
5. `renderTeeth(){ renderChecklist('teeth','screen-teeth'); }`; ветка в `go()`; ветка в `renderActiveChecklist()`; `attachChecklistHandlers(document.getElementById('screen-teeth'))`; добавить `'teeth'` в список сброса `viewDate` при клике по вкладке.
6. В `renderChecklist` — при необходимости заголовок/подпись для нового раздела.
7. **`renderHistory`** — добавить бакет для нового раздела (иначе попадёт в «кожу»).
8. `renderProgress` — при желании секция раздела.
9. Если у раздела нужна «остановка всего раздела» (как глаза) — добавить поле в `state` и ветку в `statusOf`.

**Дата старта / приёмы:** старт кожи — Настройки (или `DEFAULT_START`). Старты глаз/добавок (`EYES_START`/`SUPP_START`) и приёмы по умолчанию — хардкод; при желании вынести в Настройки.

**Когда поднимать `SCHEMA`:** если меняешь дефолт, который уже мог сохраниться у пользователя (напр. изменить/убрать авто‑приём или авто‑значение) — подними `SCHEMA` и добавь ветку в `migrate()` (менять только точное старое значение).

## 9. Как проверять (тесты)
Логику удобно гонять в Node без браузера: скрипт читает реальный `<script>` из `index.html`, исполняет его через `vm` с минимальными стабами `document`/`localStorage`/`window`, экспортирует функции (`statusOf`, `cardHTML`, `renderHistory` и т.д.) и проверяет:
- структуру (кол‑во пунктов/блоков по разделам, длительности),
- границы завершения курсов и схему Базирона,
- старты разделов и что прошлые дни «Истории» не раздуваются,
- остановку отдельного препарата (по `name` — обе дозы) и возобновление,
- раздельный счёт в «Истории» (🧴/👁/💊).
Для «живой» проверки UI поднимался временный статик‑сервер на `:8123` и открывался в браузере (превью `file://` показывает только статический снимок без JS).

## 10. Деплой (GitHub Pages)
- Репозиторий **обязан быть Public** (на бесплатном GitHub приватный отключает Pages → 404).
- Обновление: залить `index.html` (Add file → Upload files → Commit) или `git push` в `main`. Сборка ~1–2 мин.
- Данные на устройствах привязаны к origin `alihan729.github.io` и переживают обновления кода.
- **Грабли:** сделали приватным → 404 (вернуть Public, затем Settings → Pages переактивировать источник, либо в Actions «Re-run» последней сборки). Ошибка сборки `deploy: Timeout reached, aborting!` — разовый глюк выкладки (сам build проходит): помогает «Re-run all jobs» или переключение Pages Source `None`↔`main`.
